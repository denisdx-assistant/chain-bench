# chain-bench

**Независимый от публичных корпусов бенчмарк для локальных языковых моделей:
многошаговые цепочки и исполнение программ в шуме.**

Языки: [English](README.md) · **Русский** · [中文](README.zh.md)

---

## Аннотация

**Зачем это сделано.** Две цели:

1. Разработать и проверить дешёвую воспроизводимую методологию сравнения
   локальных моделей с автоматической подстройкой сложности — набор откалиброван
   так, чтобы эталонная модель ошибалась примерно в половине задач; именно в этой
   точке тест ещё различает модели.
2. Выбрать лучшую модель для конфигурации **2× V100 32 ГБ и 128 ГБ RAM**, где
   выбор решают компромисс между квантизацией, режимом контекста и скоростью.

**Что сделано.** Построены и заморожены два теста: 17 многошаговых арифметических
цепочек внутри документа шума на 20k токенов (три языка) и мысленное исполнение
20 программ на Python, в комментариях которых лежит никогда не выполняющийся код.
Эталонные ответы считает код. Сложность калибровалась на
`Qwen3.8-27B-UD-Q6_K_XL` до 41% ошибок на цепочках и 45% на программах — близко к
целевым 50%. Затем прогнаны серии для трёх конфигураций Flash-Next и для
`Qwen3.8-27B-UD-Q8_K_XL`.

**Что показали результаты.** На цепочках модели **не** разделяются: Q6 10/17, Flash-Next 12/17 при
большом бюджете и 10/17 на 32k, Q8 10/17 по-русски и 11/17 по-английски — разница
в одну-две задачи на наборе из 17, целиком внутри интервала. YaRN 1M и базовая
262k различаются на одну программу, тоже в пределах шума. Вырожденные циклы редки
и сдерживаются потоковым детектором, а не большим бюджетом.

## 1. Методология

**Тест 1 — цепочки в шуме.** Документ примерно на 20k токенов семантически
нейтрального шума (300 строк, ~72k символов) содержит цепочки утверждений и 17
вопросов. Ответ — одно целое число. Для каждого языка используется один и тот же
генератор и сид, поэтому шум параллелен и меняется только язык.

**Тест 2 — замороженные программы.** 20 программ на Python (сиды 300–319) строят
массив из 10 элементов: обмены, ветвления, циклы, рекурсия, регулярные выражения,
приведение типов и алиасинг. В комментариях и строках — код-обманка. Модель
возвращает итоговый массив и его сумму; совпадать должно и то, и другое.

**Калибровка.** Сложность повышается сначала структурой, затем объёмом шума;
маленький бюджет токенов намеренно не используется как рычаг. Эталонная модель
подгоняется примерно к 50% ошибок. Пошаговая таблица —
в [docs/calibration.md](docs/calibration.md).

**Контроль.** Одна задача на запрос; зафиксированный бюджет для класса модели;
потоковый детектор циклов; перепрогон обрывов по длине с четырёхкратным бюджетом;
фиксация происхождения в каждом прогоне. Правила —
в [docs/methodology.md](docs/methodology.md).

## 2. Серия тестов

**Наборы.** Тест 1: полный документ на 17 задач на русском, английском и китайском,
плюс переведённое подмножество из 8 задач для преемственности с первыми прогонами.
Тест 2: один замороженный набор из 20 программ, без деления по языкам. Все наборы
заморожены; новый вариант добавляется новым файлом.

**Как проводилась серия.** Каждая модель отдаётся через один локальный эндпоинт,
поэтому прогоны строго последовательны. Прогон — одна задача на запрос, бюджет и
сэмплирование записаны в [results/run-configs.json](results/run-configs.json).
Модель может занимать несколько строк ниже, если отдавалась с другим контекстом,
YaRN, температурой или бюджетом — контекст по умолчанию 262k, если иное не
сказано в имени (`+ YaRN 1M`).

**Как проводился adjustment.** Цепочки подстраивались добавлением задач на
комбинирование правил, шум оставлен на 20k токенов: развёртка показала, что 40k и
60k точность не меняют. Программы подстраивались добавлением операций, вложенности
и обманок в четырёх поколениях, пока эталонная модель не опустилась примерно до
половины ошибок.

## 4. Воспроизведение прогона

```bash
python3 scripts/run_chains_guarded.py \
    --dataset datasets/chains/ru/dataset_20k_17tasks.json \
    --model local-only --max-tokens 16000 --timeout 2400 --temp -1 \
    --out results/<model>/chains_ru_20k_16k.json

python3 scripts/run_frozen_guarded.py --dir datasets/programs/v4 \
    --model local-only --max-tokens 16000 --timeout 2400 --temp -1 \
    --out results/<model>/programs_v4_16k.json
```

`--temp -1` означает сэмплирование по умолчанию: поле не передаётся, а не
выставляется в значение. Генераторы детерминированы по сиду.

## 5. Ограничения

- Малые выборки: 17 цепочек и 20 программ. Ценность в профилях ошибок и
  относительном порядке, а не в точных долях.
- Одна конфигурация железа и один локальный эндпоинт; медиана времени включает
  очередь.
- Трёхъязычное подмножество из 8 задач — историческая сверка, а не полный перевод
  первого поколения.
- У трёх запланированных квантизаций прогонов ещё нет.

## 6. Структура репозитория

```
README.md            английский, основной
README.ru.md         русский перевод
README.zh.md         китайский перевод
docs/                методология, калибровка, результаты по задачам, журнал (англ.)
datasets/            замороженные данные + MANIFEST.json с SHA-256
results/             по папке на модель, точное имя модели
  <model>/series.json    машиночитаемый индекс прогонов
  <model>/*.json         один файл на прогон
results/run-configs.json  конфигурация отдачи по каждому прогону
results/_invalid/    пакетные эксперименты для истории, исключены из таблиц
scripts/             генераторы, раннеры, детектор циклов, сборка таблиц
```

**Оценках программ.** Прежний защищённый раннер сравнивал ответ с ключами
`array`/`sum`, тогда как в датасетах они называются `expected_array`/`expected_sum`,
поэтому все программы в тех прогонах считались неверными. Затронутые прогоны
(варианты Flash-Next) отозваны из таблиц и перезапускаются с исправленной сверкой;
оценка программ у Q6 воспроизводится по сохранённым ответам.
