# chain-bench

**Приватный бенчмарк для локальных языковых моделей: многошаговые цепочки и
исполнение программ в шуме.**

Языки: [English](README.md) · **Русский** · [中文](README.zh.md)

---

## Аннотация

Публичные бенчмарки подвержены загрязнению: модель могла видеть их задачи при
обучении. Этот набор измеряет другое — способность **удерживать зависимости
вместе**. Тест 1 погружает многошаговые арифметические цепочки в длинный
документ семантически нейтрального шума; Тест 2 просит мысленно исполнить
небольшую программу на Python, в комментариях и строках которой лежит код,
который никогда не выполняется. Эталонный ответ всегда вычисляется кодом, а не
руками.

У проекта два независимых аспекта:

1. **Стенд** — воспроизводимая методика: замороженные наборы данных, фиксация
   происхождения модели, детектор зацикливания, строгая политика перепрогона
   при обрыве по длине, результаты по папкам моделей. Он устроен так, чтобы
   прогон на другой машине позже был сравним с ранним.
2. **Текущие результаты** — небольшой честный срез того, как ведут себя три
   квантизации/конфигурации. Выборки намеренно скромные; ценность в профиле
   ошибок, а не в третьей значащей цифре.

## 1. Что измеряется

Два навыка, важных для агентных циклов и не выделяемых публичными бенчмарками:

- **Комбинирование правил в шуме.** Суммировать смещения по цепочке легко;
  выбрать и скомбинировать два правила, когда вокруг тысячи почти одинаковых
  утверждений, — нет.
- **Мысленное исполнение кода.** Комментарии и строковые константы с правдоподобным
  кодом — прямая ловушка для модели, которая читает, а не исполняет.

Записываются и точность, и астрономическое время на задачу. Вырожденное поведение
(циклы, обрывы по длине) считается отдельно от обычных неверных ответов.

## 2. Тест 1 — арифметические цепочки в шуме

- Документ примерно на 20k токенов (300 строк шума, ~72k символов) генерируется
  одним и тем же генератором и сидом для каждого языка. Шум семантически
  нейтрален: те же предикаты для других сущностей, почти совпадающие
  идентификаторы, правила про другие классы. Имена сущностей из задач в шум
  никогда не попадают.
- 17 задач покрывают суммы смещений, правила делимости, «звезду» min/max,
  ветвление, возраст с псевдонимами, последовательные проценты, пороги массы и
  цвета, пробег с делимостью, подсчёт по двум признакам, отношения, приоритет
  правил, группу против группы, способность и размер, производные свойства,
  денежную ловушку, изменение переменной и сокращение по порядку упоминания.
- Ответ — одно целое число. Эталон вычисляется кодом.

## 3. Тест 2 — замороженные программы

- 20 программ на Python (сиды 300–319) строят массив из 10 целых: обмены,
  `+=`, `-=`, `*=`, сортировка среза, разворот, условия, циклы, рекурсия,
  регулярные выражения, приведение типов через `str(a) + str(b)`, алиасинг
  (`arr2 = arr`).
- Шум — код в комментариях и строковых константах, который никогда не
  выполняется.
- Модель возвращает итоговый массив и его сумму в фиксированном формате
  (`ARRAY: [...]`, `SUM: n`). Совпадать должно и то, и другое; частичных
  баллов нет.
- Набор заморожен: каждая модель видит байт-в-байт одинаковый вход.

## 4. Правила стенда

| Правило | Значение |
|---|---|
| Одна задача на запрос | всегда для оценки; пакетные прогоны хранятся как невалидные эксперименты |
| Детектор циклов | потоковые 8-словные шинглы; обрыв, если один шингл повторился > 40 раз, метка `kind=loop` |
| Сэмплирование защищённых прогонов | temperature 0.3, `frequency_penalty` 0.3, `presence_penalty` 0.3 |
| Бюджет, класс 27B | 16k |
| Бюджет, класс Flash-Next | 32k с детектором |
| Перепрогон обрыва по длине | повтор с 4× бюджетом (131072), результат рядом с исходным |
| Происхождение | роутер опрашивается до прогона; `resolved_provider` и `resolved_model` пишутся в результат |
| Пустой ответ | считается артефактом стенда, не ошибкой модели |

**Бюджет — параметр, а не деталь.** Слишком маленький бюджет превращает сильную
модель в пустой ответ: одно рассуждение может его превысить. Слишком большой
бюджет не помогает циклу: цикл съедает любой бюджет. Измеренная поправка:
длинные генерации на трудных задачах часто оказывались вырожденным повтором,
поэтому рычаг — контроль циклов плюс умеренный бюджет, а не больший потолок.

## 6. Результаты

### 6.1 Тест 1, полный набор из 17 задач (русский, одна задача на запрос)

| Модель | Бюджет | Верно | Ошибок | Медиана времени | Медиана рассуждения | Обрывов по длине | Циклов |
|---|---|---|---|---|---|---|---|
| Qwen3.8-27B-UD-Q6_K_XL | 16k | 10/17 | 41% | 61 с | 11.9k символов | 0 | 0 |
| Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S + YaRN 1m | 65535, дефолтное сэмплирование | 12/17 | 29% | 83 с | 23.7k символов | 0 | 0 |
| Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S + YaRN 1m | 32k, с детектором | 10/17 | 41% | 82 с | — | 1 | 0 |

Прогон на 32k с детектором — единственный, где одна задача упёрлась в потолок
(задача 12). Отдельный перепрогон этой задачи на 131072 дал верное значение за
214 с, что относит её к настоящим длинным рассуждениям, а не к циклу.

### 6.3 Тест 2, 20 замороженных программ

| Модель | Бюджет | Верно | Ошибок | Медиана времени | Медиана рассуждения | Обрывов по длине | Циклов |
|---|---|---|---|---|---|---|---|
| Qwen3.8-27B-UD-Q6_K_XL | 16k | 11/20 | 45% | 296 с | — | 0 | 0 |
| Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S + YaRN 1m | 32k, с детектором | 3/20 | 85% | 129 с | 14.1k символов | 3 | 0 |

Скорость здесь — медиана астрономического времени на задачу, включая очередь.
Это не чистая пропускная способность и не сравнимо с цифрами вендоров.

### 6.4 Находки калибровки (контекст, не оценка)

- Пакетный режим — все 17 задач одним запросом — примерно в одиннадцать раз
  быстрее, но вдвое ошибочнее (4/17, 76%). Из оценки исключён.
- Рост объёма шума с 20k до 65–100k токенов не поднял долю ошибок; подняла
  структурная сложность.
- `reasoning_effort` меняет длину рассуждения (12.1k → 14.9k символов), но не
  правильность.

## 7. Качественное сравнение

1. **Q6 — сильнейшая из трёх на обоих тестах.** Она же самая медленная на
   программах (296 с медиана), потому что дольше думает перед ответом.
2. **Flash-Next — это не «Q6 с меньшим бюджетом».** На тесте 2 её провалы —
   уверенно неверные ответы с 11–16k символов рассуждения и `finish=stop`, а не
   голод. На тесте 1 точность сравнима с Q6 при большом бюджете, что указывает:
   разрыв именно в исполнении программ.
3. **YaRN не является причиной деградации.** Базовая 262k-версия дала 2/20
   против 3/20 у YaRN 1M на одном замороженном наборе — разница внутри шума
   одного прогона. Снятие YaRN точность не вернуло.
4. **Потолок важен только там, где модель справляется.** В тесте 2 обрывы по
   длине совпадают с верными ответами у обеих Flash-Next: модель, которая знает
   ответ, рассуждает достаточно долго, чтобы упереться в 32k; модель, которая
   не знает, отвечает быстро и неверно.
5. **Циклы редки и управляемы.** В зачётных прогонах со штрафами 0.3 детектор
   ни разу не сработал. Единственный цикл, наблюдавшийся раньше (до детектора),
   дословно повторял один шумовой блок и съел весь бюджет.
6. **Профиль ошибок одинаков у разных моделей.** В тесте 1 проваливаются одни и
   те же типы: комбинирование правил, выбор атрибута, сокращение по порядку
   упоминания. Простые арифметические цепочки проходят.

## 9. Воспроизведение прогона

```bash
# одна задача на запрос, с детектором, с фиксацией происхождения
python3 scripts/run_chains.py --dataset datasets/chains/ru/dataset_20k_17tasks.json \
    --model local-only --max-tokens 32000 --timeout 900 --temp 0.3 --fp 0.3 --pp 0.3 \
    --out results/<model>/chains_ru_20k_32k_guarded.json

# замороженные программы, тот же детектор
python3 scripts/run_frozen_guarded.py --dir datasets/programs/v4 --model local-only \
    --max-tokens 32000 --timeout 900 --temp 0.3 --fp 0.3 --pp 0.3 \
    --out results/<model>/programs_v4_32k_guarded.json
```

Генераторы детерминированы по сиду: одинаковые параметры дают байт-в-байт
одинаковые данные.

## 11. Ограничения

- Малые выборки: 17 цепочек и 20 программ. Выводы касаются профилей ошибок и
  относительного порядка, а не точных долей.
- Одна конфигурация железа (2× V100, один локальный эндпоинт).
- Медиана времени включает очередь и зависит от параллельных запросов.
- Трёхъязычное покрытие — подмножество из 8 задач, а не все 17.
- У четырёх запланированных квантизаций прогонов ещё нет; их строки заведены,
  чтобы результаты легли в фиксированное место.
